# 08. Deploy online for free: Vercel + Render + Neon

```
Browser ──> Vercel (frontend, static)            https://<your-project>.vercel.app
              │  /api/* and /health are forwarded (same site, so no CORS setup)
              └──> Render (backend API, Docker)   https://innovprocure-api.onrender.com
                     └──> Neon (PostgreSQL + pgvector)
```

Everything here runs on free plans (Rs 0). What goes online is the **synthetic demo world**, the
same as on your laptop: never present it as real or official statistics.

Files used: [`render.yaml`](../render.yaml) (Render blueprint), [`backend/Dockerfile`](../backend/Dockerfile),
[`.dockerignore`](../.dockerignore), [`frontend/vercel.json`](../frontend/vercel.json).

**Before you start**
- Finish the local setup first ([README](../README.md) sections 2 and 3): you need the backend venv
  on your laptop to fill the online database.
- Render and Vercel deploy **from GitHub**. They need access to the repository
  `Meghana1730/SIH`: either the repository owner signs in to Render and Vercel with GitHub and
  grants access, or the owner adds you as a collaborator first.
- Push your latest code to GitHub (`main`), including `render.yaml` and `frontend/vercel.json`.

## Step 1. Database: Neon

1. Sign up at https://neon.tech (sign in with GitHub is easiest).
2. **Create project**: name `innovprocure`, Postgres version 17, region **AWS Asia Pacific
   (Singapore)** (closest to India).
3. Open **Connect** on the project dashboard, **turn OFF "Connection pooling"** (database
   migrations need the direct connection; the host must not contain `-pooler`) and copy the
   connection string. It looks like:
   ```
   postgresql://neondb_owner:PASSWORD@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```
4. Change the start from `postgresql://` to `postgresql+psycopg://` (the driver our backend uses).
   Keep the rest exactly. This is your **DATABASE_URL**. Treat it like a password.
5. Open **SQL Editor** in Neon and run once (safety step; the migrations would try it too):
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ```

## Step 2. Fill the online database (from your laptop)

The same commands as local setup steps 4-6, pointed at Neon for this one PowerShell window.
Environment variables win over `.env`, so your local setup is not touched.

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
$env:DATABASE_URL = "postgresql+psycopg://neondb_owner:PASSWORD@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require"
$env:DB_CONNECT_TIMEOUT_SECONDS = "15"
alembic upgrade head                   # tables + pgvector
python -m app.cli.synthetic load       # the synthetic demo world
python -m app.cli.synthetic validate
python -m app.cli.analytics run        # demand -> supply -> mismatch

# Two accounts with DIFFERENT passwords (each asks for its password twice):
# 1) admin: PRIVATE, only for the team (Demo Controls -> Run intelligence pipeline)
python -m app.cli.create_user --email admin@kaushalsetu.example --name "Demo Platform Admin" --role admin
# 2) state officer: read-only; its password becomes PUBLIC (it is built into the website)
python -m app.cli.create_user --email state@kaushalsetu.example --name "Demo State Officer" --role state_officer --state Maharashtra

Remove-Item Env:DATABASE_URL, Env:DB_CONNECT_TIMEOUT_SECONDS   # back to your local database
cd ..
```

Why not `python -m app.cli.demo_users` here? It gives all six demo accounts the **same**
password. On a public website that password is visible to anyone (Vite puts `VITE_DEMO_PASSWORD`
into the JavaScript), so it would also open the admin account.

Optional but recommended: in Neon, **Branches > New branch** named `seeded-backup` now. If the
demo data is ever changed or damaged before judging, you can restore from it.

## Step 3. Backend: Render

1. Sign up at https://render.com with GitHub.
2. **New > Blueprint**, pick the `SIH` repository. Render reads [`render.yaml`](../render.yaml) and
   shows one service, **innovprocure-api** (free, Docker, Singapore).
3. It asks for **DATABASE_URL**: paste the value from step 1. Everything else is preset
   (`JWT_SECRET` is generated by Render; public sign-up is off; no AI model or embeddings).
4. **Apply**. The first build takes several minutes. On every start the service runs
   `alembic upgrade head`, then the API.
5. When it shows **Live**, open:
   - `https://innovprocure-api.onrender.com/health`: `{"status":"ok", ...}`
   - `https://innovprocure-api.onrender.com/health/db`: `"database":"connected"`, pgvector installed

   Copy the service's exact address from the top of its Render page. If it is not
   `https://innovprocure-api.onrender.com` (the name was taken, so Render added a suffix), you
   need it in step 4.

## Step 4. Frontend: Vercel

1. If your Render address is not `https://innovprocure-api.onrender.com`, replace it in
   [`frontend/vercel.json`](../frontend/vercel.json) (3 places), commit and push.
2. Sign up at https://vercel.com with GitHub. **Add New > Project**, import the `SIH` repository.
3. **Root Directory: `frontend`**. The framework preset is detected as **Vite** (build
   `npm run build`, output `dist`).
4. **Environment Variables** (for the "Enter demo" button):

   | Name | Value |
   |---|---|
   | `VITE_DEMO_EMAIL` | `state@kaushalsetu.example` |
   | `VITE_DEMO_PASSWORD` | the **state officer** password from step 2 (never the admin one) |

5. **Deploy**. Open `https://<your-project>.vercel.app`, click **Enter demo**. The screens should
   show **Live API** badges (and **Synthetic**).

Always deploy through GitHub like this, never with `vercel deploy` from your laptop or by
uploading a local `dist/` folder: a local build contains whatever is in your
`frontend\.env.local` (the local admin password). The online sign-in page shows only **Enter
demo** and the sign-in form; the list of local demo accounts appears only when running locally.

## Judging day and everyday use

- **Render's free service sleeps** after 15 minutes without visitors; the next visit wakes it,
  which takes about a minute. Meanwhile the website still works: it shows the built-in demo data
  with the note "The live API is waking up". **Open `/health` two minutes before you present**,
  then reload the site.
- **Neon suspends the database** after 5 minutes idle and wakes it automatically on the next
  query (a few seconds at most).
- **Updates**: push to `main` and both Render and Vercel redeploy by themselves. New database
  migrations run when Render restarts. After changing the synthetic data or the scoring config,
  re-run the step 2 commands (`synthetic load`, `analytics run`) against Neon.
- **Demo actions** (recommendation decisions, employer validations, pledges) are saved in each
  visitor's browser only; **Demo Controls > Reset demo** clears them on that computer.

## Security notes (public website)

- The state officer password is public on purpose: that account can only **read** synthetic
  data. Keep the admin password private and never put it into Vercel.
- `JWT_SECRET` is generated by Render. Never copy secrets from your local `.env`, and never commit
  `DATABASE_URL`.
- Public self-registration is off (`AUTH_PUBLIC_REGISTRATION=false`).
- Five wrong passwords for one email lock that email for 15 minutes. If someone locks the demo
  account, **Enter demo** falls back to the offline demo data until the lock ends.
- The backend reads each visitor's IP from the `X-Forwarded-For` header
  (`--forwarded-allow-ips='*'` in `backend/Dockerfile`). Render does not publish its proxy
  addresses, so they cannot be listed instead. Without this, every visitor would share one
  login-rate-limit bucket (30 logins per 15 minutes), which a room of judges can use up. The
  trade-off: someone calling the Render address directly can fake their IP to get around the
  per-IP limit; the per-account lockout above still protects every account.
- The API docs stay public at `https://innovprocure-api.onrender.com/docs` (useful for judges;
  every write endpoint needs an admin token).

## Troubleshooting

| Problem | Fix |
|---|---|
| Every screen says **Demo data** on Vercel | The backend is asleep or unreachable. Open `/health` on the Vercel site; if it is not JSON, check the Render service is **Live** and that `frontend/vercel.json` has the right Render address. |
| Render deploy fails at `alembic upgrade head` | `DATABASE_URL` is wrong: it must start with `postgresql+psycopg://`, use the **direct** host (no `-pooler`) and keep `?sslmode=require`. Check it in Render > Environment. |
| `NoSuchModuleError` / `No module named 'psycopg2'` | The URL starts with `postgres://` or `postgresql://`; change it to `postgresql+psycopg://`. |
| `/health/db` says pgvector is not installed | Run `CREATE EXTENSION IF NOT EXISTS vector;` in Neon's SQL Editor (step 1, item 5), then restart the Render service. |
| Render log: `JWT_SECRET is not set` | The blueprint was not used; add `JWT_SECRET` (48+ random characters) in Render > Environment. |
| **Enter demo** fails but the site loads | The state officer password in Vercel does not match step 2, or the account is locked for 15 minutes. After changing Vercel variables, **Redeploy** (they are built into the site). |
| Opening a deep link on Vercel gives 404 | Vercel is not using `frontend/vercel.json`: the project Root Directory must be `frontend`. |
| `synthetic load` from the laptop is slow | Normal over the internet (a few minutes). Choose the Singapore region for Neon. |

## Free-tier limits (checked on the official pages, 30 Sep 2026)

| Service | Free plan | Matters for us |
|---|---|---|
| [Vercel Hobby](https://vercel.com/docs/plans/hobby) | 100 GB transfer / month, personal non-commercial use | Forwarding `/api` to Render waits up to 120 s; repositories owned by a GitHub *organization* cannot be connected on Hobby (`Meghana1730/SIH` is a personal repository, so it works) |
| [Render Free](https://render.com/docs/free) | 512 MB RAM, 0.1 CPU, 750 hours / month, sleeps after 15 min idle, may restart at any time | Our API uses about 100 MB; no card needed |
| [Neon Free](https://neon.com/docs/introduction/plans) | 0.5 GB storage, 100 compute-hours / month, suspends after 5 min idle, pgvector included | Our database is about 42 MB; no card needed |

Free plans change often; check these pages again before relying on them.
